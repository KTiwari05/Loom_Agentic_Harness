# Loom v2 — Data Schemas (normative)

Every on-disk format in v2. **These shapes are law**; code conforms to this document.
All files UTF-8. All timestamps ISO-8601 with milliseconds, UTC (`2026-07-06T15:38:33.112Z`).
All UUIDs are v4 strings. Field names are camelCase in records, snake_case in Python code.

Storage roots:

```
~/.loom/
  sessions/<projectSlug>/<sessionId>.jsonl     # event log (Phase 1)
  tasks/<sessionId>/<n>.json  + .lock          # task ledger (Phase 4)
  jobs/<sessionId>/<jobId>.output              # background job stdout (Phase 3)
  memory/<projectSlug>/MEMORY.md + <name>.md   # project memory (Phase 7)
  loom.env                                     # user settings (v1, unchanged)
```

`projectSlug` = workdir absolute path with `[\\/:]` → `-` (e.g. `C--Users-asus-proj`).

---

## 1. Event record envelope (every line in the session JSONL)

```json
{
  "uuid": "8c9f…",             // required, unique
  "parentUuid": "ab12…",        // null ONLY for session-start root and compaction boundary
  "type": "user | assistant | attachment | system | queue-operation | mode | ai-title | last-prompt",
  "timestamp": "ISO-8601",
  "sessionId": "uuid",
  "cwd": "C:\\abs\\path",       // recorded per event (it can change mid-session)
  "version": "0.2.0",           // loom version that wrote the record
  "isSidechain": false,          // true for subagent records (Phase 9)
  "sidechainId": "sc_ab12cd34ef"  // ONLY on sidechain records: groups one subagent run;
                                  // the sidechain's root user record also carries
                                  // "sidechainAgentType": "explore" | "general"
}
```

Type-specific fields are merged into the same object (flat, not nested under "data").
Records with `type` in {queue-operation, mode, ai-title, last-prompt} may omit
uuid/parentUuid (they are session-level metadata, not tree nodes).

## 2. `user` record

```json
{ …envelope…, "type": "user",
  "message": { "role": "user", "content": "string OR [content blocks]" },
  "origin": { "kind": "human" | "task-notification" | "hook" | "compaction" },
  "isMeta": false,               // true = shown to model but is not a real user request
  "isCompactSummary": false,     // true = this IS the compaction summary
  "toolUseResult": {},           // structured mirror when content holds a tool_result (see §4)
  "sourceToolAssistantUUID": ""  // uuid of the assistant record whose tool_use this answers
}
```

Content blocks allowed: `{"type":"text","text":…}`, `{"type":"image","source":{"type":"base64","media_type":…,"data":…}}`,
`{"type":"tool_result","tool_use_id":"tc_…","content":"string","is_error":false}`.

## 3. `assistant` record

```json
{ …envelope…, "type": "assistant",
  "message": {
    "role": "assistant",
    "model": "openrouter/moonshotai/kimi-k2",   // ACTUAL model that produced it
    "content": [
      {"type": "text", "text": "…"},
      {"type": "tool_use", "id": "tc_01H…", "name": "read_file", "input": {…}}
    ],
    "stop_reason": "tool_use | end_turn | error",
    "usage": { "input_tokens": 0, "output_tokens": 0,
               "cache_read_input_tokens": null, "cache_creation_input_tokens": null }
  },
  "requestId": "req_…",          // provider request id if available, else local uuid
  "costUsd": 0.00123,            // Loom computes this (LiteLLM); nullable
  "isApiErrorMessage": false     // true → model MUST be "<synthetic>", content = error text
}
```

Tool call IDs: `tc_` + 24 random base62 chars. Generated by Loom if the provider
doesn't supply one; provider IDs pass through unchanged.

## 4. Tool result mirror (`toolUseResult` on the user record)

Plain text goes in the content block (that's what the model sees, truncated per limits);
the mirror carries structure for the UI — NEVER truncated the same way:

```json
{ "tool": "read_file", "ok": true,
  "target": "src/x.py",          // file path or command string; null if n/a
  "category": "file_read | file_write | file_edit | search | command | task | agent | other",
  "detail": {}                    // tool-specific: {"lines": 120} / {"exitCode": 0} / {"matches": 7}
}
```

Category mapping (used by activity aggregation, Phase 10):
read_file/list_dir→file_read · write_file→file_write · edit_file→file_edit ·
grep/glob→search · run_shell→command · task_*→task · task(subagent)→agent.

## 5. `attachment` record

```json
{ …envelope…, "type": "attachment", "attachment": { "type": "<atype>", …payload } }
```

| atype | payload |
|---|---|
| `task_reminder` | `{"content": [ledger items, §9 shape], "itemCount": n}` |
| `file` | `{"filename": "abs path", "content": "full text", "reason": "compaction" \| "recall"}` |
| `edited_text_file` | `{"filename": "abs path", "snippet": "unified diff or new excerpt"}` |
| `skill_listing` | `{"names": ["commit", …], "content": "rendered list", "isInitial": true}` |
| `deferred_tools_delta` | `{"addedNames": […], "removedNames": […], "loaded": bool}` — `loaded` absent/false = name-only advertisement; true = schemas loaded via tool_search (the "discovered" set replayed on resume and re-advertised after compaction) |
| `agent_listing_delta` | `{"addedTypes": ["explore","general"], "isInitial": true}` |
| `date_change` | `{"newDate": "YYYY-MM-DD"}` |
| `goal_status` | `{"met": bool, "condition": "text", "feedback": "verdict text"}` |
| `hook_context` | `{"hookName": "PostToolUse:write_file", "toolUseId": "tc_…", "content": "text"}` |

Attachments are rendered into the next model prompt by the context assembler
(rendering rules: module spec §5). They are never model-authored.

## 6. `system` record

```json
{ …envelope…, "type": "system",
  "subtype": "compact_boundary | stop_hook | error",
  "level": "info | warning | error",
  "content": "human-readable line",
  "compactMetadata": {            // ONLY when subtype = compact_boundary
    "trigger": "manual | auto",
    "preTokens": 0, "postTokens": 0, "durationMs": 0,
    "preservedUuids": ["…"],      // tail records kept verbatim
    "discoveredTools": ["…"],     // deferred tools loaded pre-compaction (re-advertise!)
    "reinjectedFiles": ["abs path", "…"]
  },
  "stopHook": {                    // ONLY when subtype = stop_hook
    "condition": "goal text", "met": false, "feedback": "verdict",
    "preventedContinuation": true }
}
```

`compact_boundary` records have `parentUuid: null` — they start a new tree root.
The tail records re-appended after the boundary are verbatim copies of already-logged
records and carry `isCompactTail: true` (usage/cost also zeroed): derived views that
count things (activity aggregation, stats) skip them to avoid double-counting.

## 7. Compaction summary (content of the `isCompactSummary` user record)

Sectioned markdown, produced by the summarizer model with EXACTLY these headings:

```
1. Primary Request and Intent
2. Key Technical Concepts
3. Files and Code Sections      (path + why it matters + key snippets if critical)
4. Errors and Fixes             (error → root cause → fix, one line each)
5. Problem Solving              (decisions made and why)
6. All User Messages            (verbatim list of human inputs, truncated at 200 chars each)
7. Pending Tasks                (mirror of ledger state)
8. Current Work                 (what was in flight at the boundary)
9. Next Step                    (the single concrete next action)
```

Prefix line: `This session is being continued from a previous conversation that ran out
of context. Raw transcript: <abs path to jsonl>.`

## 8. Memory files

`~/.loom/memory/<projectSlug>/<kebab-name>.md`:

```markdown
---
name: <kebab-slug>                # must equal filename minus .md
description: <one line, used for recall relevance>
metadata:
  type: user | project | feedback | reference
  originSessionId: <uuid>
---
<body: one atomic fact; absolute dates; [[other-name]] links allowed>
```

`MEMORY.md` (index, injected at session start — bodies are NOT injected):

```markdown
# Memory Index
- [Title](file-name.md) — one-line hook
```

## 9. Task ledger item — `~/.loom/tasks/<sessionId>/<n>.json`

```json
{ "id": "3",                      // stringified int, == filename
  "subject": "imperative title",
  "description": "full text",
  "activeForm": "present-continuous spinner text",
  "status": "pending | in_progress | completed",   // delete = remove the file
  "blocks": ["4"], "blockedBy": [] }
```

`.lock` file in the dir; acquire via `msvcrt.locking`/`portalocker`-style exclusive
create-retry before any write. IDs are allocated `max(existing)+1`.

## 10. `queue-operation` record

```json
{ "type": "queue-operation", "sessionId": "…", "timestamp": "…",
  "operation": "enqueue | dequeue | remove",
  "content": "prompt text (enqueue only)",
  "origin": "human | task-notification" }
```

## 11. Background job notification (the enqueued synthetic prompt)

```
<task-notification>
  <task-id>k3v9x0q2p</task-id>
  <status>completed|failed</status>
  <exit-code>0</exit-code>
  <output-file>~/.loom/jobs/<session>/<id>.output</output-file>
  <summary>Background command "<description>" completed (exit code 0)</summary>
</task-notification>
```

Job IDs: 9 chars, lowercase base36, first char alphabetic.

## 12. `mode`, `ai-title`, `last-prompt` records

```json
{ "type": "mode",        "mode": "normal | auto | plan", "sessionId": "…", "timestamp": "…" }
{ "type": "ai-title",    "aiTitle": "short title",       "sessionId": "…", "timestamp": "…" }
{ "type": "last-prompt", "lastPrompt": "text",  "leafUuid": "uuid of newest record", "sessionId": "…" }
```

## 13. Size limits (enforced at result-normalization time)

| Thing | Limit |
|---|---|
| Tool result text into model context | 30,000 chars, marker `…[truncated]` |
| read_file default | 2,000 lines |
| grep output | 250 lines |
| file attachment | 100 KB |
| compaction summary target | ≤ 4,000 tokens |
